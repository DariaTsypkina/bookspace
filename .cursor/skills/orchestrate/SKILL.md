# /orchestrate — пакетный оркестратор (Bookspace)

Использовать **только** при явном вызове `/orchestrate` или `/оркестратор`.

Канон git/close: [feature-workflow § Close + merge](../../docs/tech/feature-workflow.md).  
Полный промпт оркестратора: [orchestrator-prompt.md](./orchestrator-prompt.md) — **прочитай целиком перед стартом**.

## Ввод

Параметры **после** slash в том же сообщении — блок **ВХОД** (см. шаблон ниже).  
Если **КЛЮЧИ ЗАДАЧ** пуст — один короткий вопрос:

> Какие bd-ключи в набор? (листовые задачи или эпики — эпики развернутся в детей)

Не начинать оркестрацию без ключей.

## Что делать

1. Прочитать [orchestrator-prompt.md](./orchestrator-prompt.md) **целиком** — источник истины протокола.
2. Подставить параметры из сообщения пользователя в блок **ВХОД** промпта.
3. Действовать **строго** по промпту: ты — оркестратор, код пишут только субагенты (Agent tool), последовательно, по одному.
4. Не задавать вопросов пользователю — автономные решения по правилам проекта.

## Шаблон ВХОД (пользователь подставляет в сообщение)

```
РЕЖИМ ВЕТКИ: feat/bookspace-bd-<epic-id> | текущая
ЗАЛИВАТЬ В develop: Нет | Да
ЛИМИТ ВРЕМЕНИ (МСК): нет | HH:MM | Nh/Nm
КЛЮЧИ ЗАДАЧ:
<bd-id по одному на строку>
```

**РЕЖИМ ВЕТКИ** — имя **сборочной** ветки, куда стекается весь набор (конвенция git-flow: `feat/bookspace-bd-<epic-id>`). Указывай id **эпика**, объединяющего подзадачи из списка ключей: если в наборе листья `bd-cq7.7`, `bd-cq7.8` — сборочная `feat/bookspace-bd-cq7`; если ключ — сам эпик — его id. Значение `текущая` — сборочной служит текущая ветка (не `develop`/`master`).

### Пример вызова

```
/orchestrate
РЕЖИМ ВЕТКИ: feat/bookspace-bd-cq7
ЗАЛИВАТЬ В develop: Нет
ЛИМИТ ВРЕМЕНИ (МСК): 4h
КЛЮЧИ ЗАДАЧ:
bd-cq7.7
bd-cq7.8
```

## Запреты

- Не писать prod-код самому — только субагенты.
- Не запускать субагентов параллельно.
- Не мержить задачи напрямую в `develop` (только сборочная → develop в финале при ЗАЛИВАТЬ=Да).
- Не трогать `master`.
- Не объявлять задачу завершённой без зелёных тестов и Playwright.
