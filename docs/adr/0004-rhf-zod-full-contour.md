# ADR 0004: Единый контур валидации и форм на RHF + Zod

- **Статус:** accepted
- **Дата:** 2026-07-27
- **Accepted:** 2026-07-28 (человек)

## Контекст

В `apps/web` формы реализованы вручную (`useState` + `onSubmit`), а в `apps/api` валидация DTO построена на `class-validator`. Это создаёт два разных подхода к валидации, повышает риск расхождения контрактов между frontend и backend и увеличивает стоимость изменений.

Ранее для UI уже принят инкрементальный DX-трек (ADR 0003). Для форм и валидации нужен аналогичный трек: единая схема, поэтапная миграция, прозрачный контроль рисков.

## Решение

1. Принять целевой стек:
   - web-формы: `react-hook-form` + `zod@v4` + `@hookform/resolvers` + паттерн `shadcn Form`;
   - api-валидация: `zod` + `nestjs-zod`;
   - shared-контракты: `packages/schemas` как единый источник схем.
2. Мигрировать инкрементально по принципу **foundation + on-touch**:
   - сначала foundation для web/api/shared;
   - затем доменно: по страницам, фичам и endpoint-группам;
   - новый код сразу писать только на RHF+Zod.
3. Цель эпика: по завершении трека полностью убрать `class-validator` и legacy-валидацию форм.
4. OpenAPI для Nest — через `nestjs-zod` (`createZodDto` + `cleanupOpenApiDoc` / актуальный setup библиотеки). Собственный OpenAPI-генератор не вводим.
5. Формат ошибок валидации API зафиксировать как единый JSON-контракт для `400 validation errors`.
6. При единой Zod-схеме допускается различать UX-тексты на web (friendly/localized messages), не меняя API-контракт (`code`/`path`/`message`) и сами ограничения схемы.

## Последствия

- Плюсы:
  - один источник правды для входных контрактов;
  - меньше дублирования правил валидации;
  - более предсказуемые формы в web и единый DX-подход;
  - OpenAPI из Zod без ручных `@ApiProperty` и без своего codegen.
- Минусы:
  - OpenAPI зависит от возможностей `nestjs-zod` (если чего-то нет — workaround в рамках библиотеки, не свой генератор).
- Итог миграции (2026-07-29, bd-0t0.11):
  - runtime app-код без `class-validator` / `class-transformer` imports;
  - прямые зависимости удалены из `apps/api`; валидация — только Zod + `nestjs-zod`;
  - optional peer-записи в lockfile у Nest-пакетов допустимы без использования в app source.
- Отложено:
  - потенциальный рефактор структуры shared-схем после стабилизации MVP.
