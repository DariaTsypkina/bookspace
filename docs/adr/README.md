# Architecture Decision Records (ADR)

Короткие записи решений «почему так», не дублируют длинный tech-док.

## Когда писать ADR

- Выбор или смена стека, БД, auth, очередей, LLM-провайдера.
- Формула агрегации рейтингов, политика matching/автопубликации.
- Отказ от чего-то из MVP или сознательный trade-off.

## Имя файла

`NNNN-краткий-slug.md` — например `0001-stack-mvp.md`. Нумерация сквозная.

## Шаблон

```markdown
# ADR NNNN: Заголовок

- **Статус:** proposed | accepted | superseded
- **Дата:** YYYY-MM-DD

## Контекст

Зачем нужно решение.

## Решение

Что выбрали.

## Последствия

Плюсы, минусы, что откладываем.
```

После принятия ADR добавить ссылку в [docs/README.md](../README.md) и при необходимости в соответствующий файл `docs/tech/`.
