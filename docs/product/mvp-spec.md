# Спецификация: Книжная вселенная (MVP)

## 1. Цель продукта

Русскоязычный веб-сервис для читателя: вести коллекцию и прогресс (как Goodreads / LiveLib) и исследовать **связи** между книгами, персонажами, мирами и порядком чтения. Каталог общий и закрытый для правок пользователей. Общедоступны: **рейтинги**, **подборки**, **рекомендации**. Отличающая фича: блок **«для понимания»** (влияние и контекст) — **только у книг, которым это нужно**, собираемый из открытых источников с помощью LLM и автопубликуемый.

## 2. Аудитория и язык

- Основной пользователь: читатель.
- Язык UI и контента каталога: **русский в первую очередь**.
- Вторично (после MVP): фанаты вселенных, исследователи — через те же сущности связей.

## 3. Платформа и UX-принципы

- **Веб + PWA**, подход **mobile first**.
- Визуальный тон: **минимализм**, спокойные нейтральные тона, «читальная»; типографика и воздух важнее плотности маркетплейса.
- Спойлеры: **мягко** — предупреждение «могут быть спойлеры», после подтверждения весь контент открыт (без размытия по прочитанному).

## 4. Роли и доступ


| Роль    | Возможности                                                                                      |
| ------- | ------------------------------------------------------------------------------------------------ |
| Гость   | Просмотр каталога, рейтингов, подборок, рекомендаций; просмотр публичных коллекций пользователей |
| `user`  | Регистрация/вход, **публичная** коллекция, оценки, заметки, полки, цель года                     |
| `admin` | Каталог, импорт, дедупликация, рейтинги/подборки, модерация связей и context-списков             |


Подписки и лента активности **не входят в MVP**, но публичный профиль с коллекцией — да. Модель не должна блокировать соцфункции позже.

Аутентификация MVP: **email + пароль**, **Google**, **Яндекс**.

## 5. Монетизация

- MVP: всё бесплатно.
- Позже: **премиум** (расширенная статистика, расширенные цели, экспорт и т.п.) — заложить флаг подписки в модели пользователя, без реализации биллинга в MVP.

## 6. Доменная модель (сущности и связи)

### 6.1 Каталог (только admin / импорт)

```mermaid
erDiagram
  Work ||--o{ Edition : has
  Work ||--o{ WorkRelation : from
  Work ||--o{ WorkRelation : to
  Work ||--o{ ContextReading : subject
  Work ||--o{ ContextReading : recommended
  Work }o--o{ Author : writtenBy
  Work }o--o{ Series : belongsTo
  Work }o--o{ Character : features
  Work }o--o{ Place : setIn
  Place }o--o| World : partOf
  Character }o--o{ Character : relatedTo
  Work ||--o{ ExternalId : mapped
  Author ||--o{ ExternalId : mapped
  Ranking ||--o{ RankingEntry : contains
  Collection ||--o{ CollectionEntry : contains
  Work ||--o{ RankingEntry : listedIn
  Work ||--o{ CollectionEntry : listedIn
```



Ключевые сущности:

- **Work (произведение)** — каноническая единица каталога (логическое произведение, не один тираж).
- **Edition (издание/перевод)** — язык, переводчик, издательство, год, ISBN и т.д.
- **Author**, **Series**, **Character**, **World**, **Place** (локации; для фэнтези — отдельные миры).
- **WorkRelation** — типы: `sequel`, `prequel`, `related`, `adaptation` (по мере нужды); используется и для **порядка чтения**.
- **ContextReading** — «для понимания»: `subject_work` → `recommended_work`, `importance_rank` (меньше = важнее / сильнее влияние), `why_text` (кратко «зачем»), `status` (`draft`/`published`/`rejected`), служебные поля источника (только admin). Блок показывается **только** если у произведения есть опубликованные записи ContextReading (не у всех книг).
- **ExternalId** — id из Open Library и др. для дедупликации.
- **CharacterAppearance**, **CharacterRelation** — появление в книгах и связи между персонажами.
- **Ranking (рейтинг/топ)** — общедоступный упорядоченный список, напр. «Топ-100 мировой классики», «Топ-50 книг о Великой Отечественной войне». Имеет название, описание, тип/тему.
- **RankingEntry** — позиция книги в рейтинге (`rank`, `Work`).
- **Collection (подборка)** — общедоступная тематическая подборка без обязательного жёсткого ранжирования «кто лучше», напр. «Главные книги постмодернистской литературы», «Поэзия Серебряного века».
- **CollectionEntry** — книга в подборке (опциональный порядок показа).
- **ExternalRankingSource** — внешний авторитетный топ/список (The Greatest Books, Amazon Editors, Modern Library, Le Monde «100 books of the century», The Guardian «100 best» и др.), из которого импортируются позиции для последующей агрегации.
- **AggregatedScore** (служебно) — вклад внешних источников и/или внутренний скор книги для построения «объективных» рейтингов приложения.

Пользователь **не** создаёт и не редактирует сущности каталога, рейтингов и подборок приложения (свои пользовательские полки — отдельно, см. 6.2).

### 6.2 Личный кабинет (user)

- **UserBook**: статусы `want` | `reading` | `read` | `abandoned`, оценка **1–10**, привязка к `Work` (и опционально к `Edition`).
- **Note / Quote** — заметки и цитаты; у каждой записи пользователь выбирает видимость: **публичная** или **приватная**.
- **Shelf / Tag** — пользовательские полки и теги (видны в рамках публичной коллекции).
- **ReadingGoal** — цель на год (N книг).

### 6.3 Задел на будущее (модель допускается, UI/API нет)

- Интерактивный граф.
- События и временные линии.
- Подписки и лента активности.
- Премиум-флаги и расширенная статистика.

## 7. Функции MVP

### 7.1 Каталог (гость + user)

- Поиск и карточки: книга, автор, серия, персонаж, мир/локация.
- Страница книги: авторы, серия, издания/переводы, продолжения/приквелы, **порядок чтения**, персонажи, места/мир, **рекомендации** похожих книг; блок **«Для понимания»** — **только если для книги есть опубликованный ContextReading**.
- Страница персонажа: книги появления, связи с другими персонажами.
- Порядок чтения серии/вселенной.
- Мягкое предупреждение о спойлерах на страницах со связями/персонажами.

### 7.2 Личный кабинет (user)

- Добавить книгу на полку, сменить статус, поставить оценку 1–10.
- Заметки и цитаты (каждая — публичная или приватная по выбору пользователя); полки/теги; цель «N книг в год» и простой прогресс (по числу со статусом `read` в текущем году).
- Коллекция **публична**: гости и другие пользователи могут открыть профиль и видеть полки, статусы, оценки и **публичные** заметки/цитаты.

### 7.3 Общедоступные рейтинги, подборки и рекомендации

Эти разделы **обязательны в MVP** и доступны без входа.

**Рейтинги (топы)** — режим автопубликации (A)

- Примеры: «Топ-100 мировой классики», «Топ-50 книг о ВОВ».
- Упорядоченные списки книг с позициями.
- Источники для построения рейтингов приложения:
  - внешние авторитетные списки: The Greatest Books, Amazon Editors’ picks, Modern Library Top, Le Monde — 100 books of the century, The Guardian — 100 best и **максимально возможное число** аналогичных открытых источников;
  - при наличии — мнения/ранжирования исследователей и писателей (как дополнительный сигнал, не единственный).
- Цель: на анализе многих источников составить **максимально объективные рейтинги**, которые показываются в приложении (агрегация позиций/упоминаний из `ExternalRankingSource` → наши `Ranking` / скоры книг).
- Пайплайн: импорт внешних списков → нормализация и сопоставление с `Work` → агрегация скоров → **автопубликация** рейтинга в каталог. Admin может править или снять с публикации выборочно.
- Пользователю источники агрегации в MVP **не обязаны** показываться по каждой позиции; полные данные источников — в админке.

**Иностранные источники и язык (рейтинги / каталог / context / подборки)**

Многие внешние материалы — на английском, французском и др. Для продукта это **не** требует перевода статей и эссе целиком.

1. Из источника извлекается **структура**: позиция в топе / название / автор / год / ISBN при наличии; для ContextReading — кандидаты книг и краткое обоснование. Полный текст эссе не перепечатывается.
2. Сопоставление с каталогом: ISBN / Open Library / другие `ExternalId`; при отсутствии id — fuzzy match + LLM-помощь («Ulysses» / «Улисс» → один `Work`). В UI всегда показывается **русское** каноническое название произведения из нашей БД.
3. Названия и описания **наших** рейтингов и подборок в UI — **на русском** (LLM или правила генерируют русский заголовок/описание при публикации; оригинал источника хранится в админке).
4. Текст `why_text` в блоке «Для понимания» и пользовательские подписи в подборках — **на русском** (если источник на другом языке, LLM формулирует краткое обоснование по-русски; сырой фрагмент источника — только в админке).
5. Тексты источников в админке могут оставаться на языке оригинала; пользователю их не показываем.
6. Если уверенного сопоставления с `Work` нет — позиция/связь уходит в очередь «не сматчено» (не ломает весь рейтинг или список); после появления книги в каталоге или ручного merge запись подтягивается.

**Подборки**

- Примеры: «Главные книги постмодернистской литературы», «Поэзия Серебряного века».
- Тематические общедоступные списки (акцент на теме/эпохе/направлении, а не на «кто №1»).
- Наполнение: admin и/или импорт/LLM-пайплайн с опорой на открытые кураторские и исследовательские материалы; автопубликация с возможностью правки в админке.

**Рекомендации**

- Общедоступный блок на странице книги и/или отдельный раздел «вам может быть интересно» (для гостя — на основе связей каталога и популярности/рейтингов; для вошедшего пользователя — дополнительно с учётом его полки и оценок).
- Эвристики MVP (связи, жанр/серия/авторы/мир, пересечение с рейтингами), не отдельная ML-платформа.
- Отдельно от ContextReading («для понимания» ≠ «рекомендации»).

### 7.4 ContextReading + LLM (отличие продукта)

**Требование пользователя:** не вносить списки вручную; опираться на открытые материалы авторитетных исследователей; сортировка по степени влияния; блок **не у всех книг**, а только у тех, которым контекстное чтение действительно нужно (сложная интертекстуальность, сильная зависимость от предшественников и т.п.).

**Пайплайн:**

1. Отбор кандидатов книг, «требующих» блока (правила/очередь admin / эвристика + LLM-классификация «нужен ли context»).
2. Для выбранного `Work` собрать открытые источники (статьи, предисловия, библиографии — whitelist доменов/типов на старте).
3. LLM извлекает кандидатов «что читать / что влияло», краткий `why_text`, предлагаемый `importance_rank`.
4. Сопоставление кандидатов с каталогом (по названию/автору/ExternalId); при отсутствии — черновик `Work` или очередь «создать книгу».
5. **Автопубликация** в каталог (`status = published`).
6. В админке: полные данные об источнике (URL, фрагмент, модель, дата); возможность править порядок, текст, снять с публикации (тогда блок на странице книги исчезает, если опубликованных записей не осталось).
7. Пользователю **источники не показываются**; только список книг + «зачем» + при желании дисклеймер («список составлен автоматически»).

Риски: галлюцинации, качество источников, авторские права на длинные цитаты (хранить краткие выдержки и URL, не перепечатывать эссе целиком).

### 7.5 Админка

- CRUD каталога; импорт из открытых источников + своя БД.
- **Дедупликация:** ключи ISBN / ExternalId; fuzzy match по нормализованному названию + автор + год; UI «возможные дубликаты» → merge.
- Управление рейтингами и подборками; импорт внешних топов (`ExternalRankingSource`); запуск/просмотр агрегации «объективных» рейтингов.
- Очередь/список ContextReading для выборочной правки после автопубликации; пометка книг «нужен / не нужен» блок «для понимания».
- Запуск LLM-пайплайна по книге или пачкой.

### 7.6 PWA

- Установка на домашний экран, базовый offline для оболочки и недавно открытых страниц (каталог целиком офлайн не требуется в MVP).

## 8. Нефункциональные требования (кратко)

- Mobile first, доступность базового уровня (контраст, размеры тач-целей).
- Русская локаль дат/чисел; SEO для публичных страниц каталога, рейтингов, подборок и профилей.
- Приватность: коллекция (полки, статусы, оценки) **публична**; заметки/цитаты — по флагу пользователя (публичные видны на профиле, приватные — только владельцу).
- Аудит для admin-операций merge, правок ContextReading, рейтингов и подборок.
- Язык UI и отображаемых названий каталога/рейтингов/подборок — русский; сырые иностранные источники — в админке и в пайплайне сопоставления.

## 9. Критерии приёмки MVP (checklist)

- Гость открывает книгу, видит связи, порядок чтения, персонажей, мир, рекомендации; блок «Для понимания» — только при наличии данных.
- Гость видит общедоступные **рейтинги** (в т.ч. автособранные из внешних топов), **подборки** и **публичную коллекцию** пользователя (включая публичные заметки).
- User регистрируется (email/Google/Яндекс), ведёт статусы, оценки 1–10, заметки/цитаты с выбором видимости, полки, цель года; коллекция публична.
- Admin импортирует/создаёт книги без дублей (merge), импортирует внешние топы (в т.ч. иноязычные) с сопоставлением на русские `Work`; агрегация рейтингов автопубликуется; LLM context — для книг, которым он нужен; сырые источники видны только в админке.
- Работает как PWA на телефоне; UI спокойный минималистичный, на русском.
- Нет: подписок и ленты, интерактивного графа, таймлайна событий, биллинга, правок каталога пользователем.
